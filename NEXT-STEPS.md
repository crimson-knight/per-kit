# Next steps

The free kit runs one task at a time, on files you hand it, while you watch. That is on
purpose: it is the smallest version of the loop that is safe to run on day one. Here is
what it leaves out, and what each step looks like when you want it.

## 1. Connect your real systems

Every run report lists what the run could not reach. The usual list: the accounting system
the invoices came from, the inbox the messages live in, the CRM the leads belong in, and
the send button. Connecting those means read access with the narrowest permissions that
work, drafts that land in the real tool for a person to approve, and a log of every action
the agent takes. The planning step stays the same; the inputs stop being exports.

## 2. Scheduled, unattended runs with safety gates

The kit asks you before it starts. A scheduled run (invoices every Monday at 7, inbox every
morning) has no one to ask, so it needs gates in place of you: a fixed list of actions the
agent may take, a hard stop on anything that sends money or messages without approval, a
check that compares each run's output against the source data, and a short report waiting
for you when you sit down. Your `lessons.md` from these free runs becomes the starting rule
set.

## 3. Panel planning for high-stakes work

One planner is fine for a weekly reminder batch. For a pricing change, a hiring plan, or a
system migration, several planners work the same problem from different angles (cost,
risk, customer impact, the fastest path), and their plans are merged and checked against
each other before anyone acts. It catches the assumption a single plan misses.

## Talk it through

Bring a run report. The "Estimated vs actual time" table and the "What this run could not
do" list are the agenda: which of your weekly tasks to connect first, and what it saves.
